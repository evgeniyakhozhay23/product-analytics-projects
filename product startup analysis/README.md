# Продуктовый анализ стартапа маркетплейса

### Условие кейса и данные

Karpov Courses, курс "Аналитика данных" (https://karpov.courses/analytics), модуль "Продуктовая аналитика и A/B тесты"

В рамках проекта проводится оценка нового маркетплейса, который только начинает продажу товаров. Выручка маркетплейса стоит на месте в течение нескольких месяцев.

### Структура данных
При проведении исследования использовались данные из трех датасетов.

*olist_customers_dataset.csv* — таблица с уникальными идентификаторами пользователей
- customer_id — позаказный идентификатор пользователя
- customer_unique_id — уникальный идентификатор пользователя (аналог номера паспорта)
- customer_zip_code_prefix — почтовый индекс пользователя
- customer_city — город доставки пользователя
- customer_state — штат доставки пользователя
*olist_orders_dataset.csv* —  таблица заказов
- order_id — уникальный идентификатор заказа (номер чека)
- customer_id — позаказный идентификатор пользователя
- order_status — статус заказа
- order_purchase_timestamp — время создания заказа
- order_approved_at — время подтверждения оплаты заказа
- order_delivered_carrier_date — время передачи заказа в логистическую службу
- order_delivered_customer_date — время доставки заказа
- order_estimated_delivery_date — обещанная дата доставки
*olist_order_items_dataset.csv* — товарные позиции, входящие в заказы
- order_id — уникальный идентификатор заказа (номер чека)
- order_item_id — идентификатор товара внутри одного заказа
- product_id — ид товара (аналог штрихкода)
- seller_id — ид производителя товара
- shipping_limit_date — максимальная дата доставки продавцом для передачи заказа партнеру по логистике
- price — цена за единицу товара
- freight_value — вес товара 

Cтатусы заказов в таблице olist_orders_dataset:
- created — создан;
- approved — подтверждён;
- invoiced — выставлен счёт;
- processing — в процессе сборки заказа;
- shipped — отгружён со склада;
- delivered — доставлен пользователю;
- unavailable — заказ отменён по причине недоступности товара;;
- canceled — отменён

### Содержание проекта
**Цель проекта:** проанализировать метрики продукта, выявить причины отсутствия роста в метриках.

**Инструменты:** Python, seaborn, matplotlib, operator

Для достижения поставленной цели я решила следующие **задачи**:

**1. Провела предварительный анализ данных**

**2. Оценила месячный retention в оформление заказа**

*Методы:* когортный анализ, визуализация результатов через тепловую карту

На основе выводов, полученных на этапе предварительного анализа данных, определила, каких пользователей учитываем в retention

**3. Проверила на наличие product/market fit**

На основе когортного анализа и визуализаций проверила, существует ли product/market fit. 
Выявила причины его отсутствия на основе анализа данных:
- определила процент задержек фактической доставки по сравнению с ожидаемой (отдельного для доставленных и тех, которые еще находятся в пути)
- определила долю задержек передачи заказов в логистическую службу со стороны компании
- выявила долю случаев, когда клиенты сталкивались с проблемами в осуществлении оплаты по заказу

**4. Определила 5 основных метрик продукта, которые необходимо контролировать для максимизации прибыли компании**

Метрики отражают:
- Рост объёма продаж маркетплейса: Gross Merchandise Value (GMV)
- Объем аудитории, на которых направлена ценность продукта: Monthly Active Users (MAU)
- Заинтересованность новых клиентов в продукте: конверсия в покупку
- Вовлеченность клиента в продолжение использования продукта: Retention
- Денежное выражение вовлеченности клиента: Average Revenue per User (ARPU).

Все метрики и их скользящее среднее, кроме третьей (которую нельзя оценить на имеющихся данных), были визуализированы. 

**5. Приоритизировала гипотезы**

*Методы:* фреймворк ICE (Impact-Confidence-Ease)

Оценила Impact 3 предложенных гипотез для улучшения продукта: выявила, каков масштаб ожидаемых изменений, которые повлечет предлагаемое нововведение в продукт

**6. Сформулировать метрики, на которые влияет гипотеза**

Сформулировала целевые, прокси, guardrail метрики

**7. Подготовила отчет для продукт-менеджера по проделанной работе**

- Сформулировала проблемы, которые есть в продукте и их причины
- Сделала выводы по итогу исследования на основе результатов, полученных в ходе реализации задач
- Сформулировала рекомендации по продукту

**8. Загрузила результат в Gitlab**

### Ключевые выводы
Когортный анализ показал очень низкий retention по всем когортам. Медианный retention 1-го месяца для всех когорт составляет 0.3658%, а медианны retention последующих месяцев стремится к 0%. У продукта отсутствует Product/market fit. В больше 8% случаев заказы не были доставлены в запланированный срок. Наблюдаются задержки в обработке платежей: в 75% это занимает 5-12 дней. Половина заказов не была доставлена в планируемый срок до логистической службы.
